# 课程表与小程序起始页功能开发报告

**日期：** 2026年9月16日  
**项目：** 邵小利志愿服务队 · 干事考勤系统  
**范围：** 微信小程序端

## 一、需求与实现结论

本次新增个人课程表功能，并在设置中增加“小程序载入起始页”选项。课程表数据暂采用按登录账号隔离的本地缓存，不新增后端接口或 Prisma 表，适合个人课表且不会改变现有服务端数据。

课程表支持：

- 教务系统 JSON 导入；
- 手动添加、编辑和删除；
- 课程名、教师、教室、星期、起止节次、上课周次和备注；
- 按第 1–20 周筛选，按星期查看当前周课程；
- 导入前确认，避免意外覆盖已有手动课程。

## 二、样例 JSON 适配

导入解析器同时接受已经规范化的数组，以及含 `courses`、`schedule` 或 `items` 数组的 JSON。无法识别课程名或没有有效记录时会拒绝导入。

## 八、当前周自动定位与滚动（2026-09-17 新增）

需求：打开课程表时自动停在当前周，并滚动到今天那一栏，不用每次手动翻。2026-09-17 处于第 3 周。

实现要点：

- 课程表存储新增 `startDate`（第 1 周周一）。在课程表页选择「学期起始日」后写入，选任意一天都会归一化到那一周的周一；导入 JSON 只替换课程、保留该日期（此前导入是整表覆盖，会把日期一起清掉）。
- `computeWeekNumber(startDate, today)` 以周一为一周起点计算周次：未设置起始日返回 0，早于起始日的日期按第 1 周，超过 20 周时在选择器里夹到最后一周。
- 打开页面时（`onLoad` 与首次 `onShow`）自动把周次切到当前周，并用 `wx.pageScrollTo({ selector: "#day-N" })` 滚到今天；只在本次进入时生效，从编辑弹窗或其他页面返回时不会把用户手选的周次拉回去。
- 今天那一栏加高亮描边和「今天」标签，且只在查看当前周时出现，避免翻到第 5 周却标着「今天」。
- 周次卡片新增：当前周徽标、选中周的日期范围（如「9月14日 - 9月20日」）、「学期起始日」日期选择器，以及「回到本周（第 N 周）」按钮（回到当前周并滚到今天）。

验证：在 node 下 mock `wx` / `getApp` / `Page` 跑页面逻辑，覆盖固定日期用例（8/31→第 1 周、9/7→第 2 周、9/14 与 9/17 与 9/20→第 3 周、9/21→第 4 周、早于起始日→第 1 周）、非法起始日与非法日期回退、手动切周后不被拉回、点击「回到本周」、设置起始日的归一化（9/1→8/31）、导入保留起始日，以及自动滚动目标为 `#day-4`。滚动动画与真机手感仍需在微信开发者工具/真机确认。

## 九、课程表进入考勤页 + 导入失败排查（2026-09-17 第二轮）

### 需求与结论

课程表原入口藏在「我的 → 课程表」，太深。现在**考勤页的第一个 Tab 就是课程表**，并在登录后默认停在该 Tab；值班表降为第二个 Tab，功能不变。考勤页不做冲突检测（课程与值班本来就互斥），课程表在考勤页是**只读浏览**，导入/编辑仍回课程表页。

### 其它改动

- 考勤页 Tab 序号整体后移一位（`课程表 0 / 值班表 1 / 会议 2 / 请假 3 / 统计 4`），`loadTab()` 的 `switch` 已同步重编号——这是本次最容易改错的地方，已用「切 Tab 派发」用例逐项验证。

- 切回考勤页的课程表 Tab 会重新读缓存，因此在课程表页改完课程回来立刻可见。

### 导入失败的定位与备用通道

用户反馈「JSON 上去没法读取」，界面上只看到一句无信息量的「无法读取文件」。经检查，样例文件本身没问题：45 KB、UTF-8 无 BOM、`kbList` 27 条、`zcd` 形如 `1-5周,7-14周`，可正常解析。因此问题出在小程序侧的文件读取。

**已定位的根因**：在微信开发者工具模拟器里，`wx.chooseMessageFile` 从电脑对话框选中的文件返回的是虚拟临时路径 `http://tmp/<hash>.json`，紧接着 `wx.getFileSystemManager().readFile` 会失败：

```
readFile:fail http://tmp/5VT7wQHQu8Sn9023f0ba307d223b8a33005667891c20.json not found
```

即文件根本没落到可读的文件系统里，属于开发者工具模拟器的限制，不是课表文件或解析逻辑的问题；真机从微信聊天（如文件传输助手）里选文件返回的是 `wxfile://` 路径，通常可正常读取。

针对这一点做了四项改动：

1. `readFile` 失败时**重试一次**（临时文件偶尔晚一步就绪），仍失败再提示；
2. 命中 `http://tmp/` 或 `not found` 时不再甩英文报错，而是给出可执行方案：改用「粘贴 JSON」，并说明真机一般正常；其它失败仍显示原始 `errMsg` + 文件路径，便于继续排查；
3. 文件路径兼容 `path` 与 `tempFilePath`，选择器取消不再误报失败；
4. 新增**「粘贴 JSON」**通道（`wx.getClipboardData`），开发者工具里目前最可靠的导入方式：在电脑上打开 JSON → 全选复制 → 小程序里点「粘贴 JSON」；
5. JSON 解析失败改为可读提示（原来会直接抛出 V8 的英文报错）。

### 验证

用真实教务 JSON（`课表_525070201508_2026_3.json`）跑通端到端逻辑：

## 十、自动滚动 / 起始页路由 / 设置位置（2026-09-17 第三轮）

针对三条反馈逐一修正。

### 1. 进入课程表自动滚到今天

原实现用 `wx.pageScrollTo({ selector })`，在开发者工具里不稳定（时好时坏）。改为**先测量、再按数值滚动**：

- 用 `wx.createSelectorQuery()` 取 `#day-<todayWeekday>` 的 `boundingClientRect().top` 与 `selectViewport().scrollOffset().scrollTop`，算出 `scrollTop = 当前滚动量 + 元素 top - 预留高度`，再 `wx.pageScrollTo({ scrollTop })`。
- 卡片尚未渲染（`rect.top` 不是数字）时最多**重试 3 次**（间隔 200ms），首次延迟 120ms 等布局稳定。
- 预留高度由页面传入：课程表页 `stickyHeaderOffset: 16`，考勤页（有吸顶 Tab 条）`stickyHeaderOffset: 76`。
- 仅当「当前展示的是本周」且「有课程」时才滚；`courseAutoScrolled` 标记避免重复触发，`force` 参数用于「回到本周」和切回课程表时强制再滚一次。

### 2. 起始页选「课程表」应落到考勤页的课程表子页

原先 `openStartPage()` 把 `schedule` 当普通页面 `switchTab` 过去，结果落到个人页里的课程表入口。修正：

- `app.js` 的 `openStartPage()` 里把 `schedule` / `duty` 从普通路由表移除，改为写 `globalData.pendingDutyTab`（课程表=0、值班表=1）后 `wx.switchTab("/pages/duty/duty")`；其余页面仍走原路由表。
- `duty.js` 的 `onShow()` 读取 `pendingDutyTab` 并消费（读完置 `null`），用**局部变量**承接新 tab 再 `loadTab`，不依赖 `setData` 的同步时序；置位后同步调用 `autoScrollToToday(true)`。
- `onTabChange` 切到课程表时改为重置 `courseAutoScrolled` 后调 `loadCourseView()`（内部 `setData` 回调负责滚动），避免同一次切换滚动两遍。

### 3. 周次 / 起始日设置移到页面最下面

`templates/course-schedule.wxml` 重排：**日期列表在最上，设置卡片（当前周次 + 学期起始日 + 回到本周）放最后**，`showManage` 的「导入 / 编辑课程表」入口在设置区之后。这样打开页面第一屏就是今天的课，不用先划过设置。两个复用该模板的页面（课程表页、考勤页）同步生效。

## 十一、课表 PDF 导入（2026-09-17 第四轮）

### 需求与可行性结论

主人希望「导入课表」能直接吃教务系统导出的 PDF。问题：**能不能纯算法做，不依赖任何外部 API？**

结论：**取决于 PDF 的类型。**

- **文本型 PDF**（页面由文字绘制指令构成）→ **可以纯算法解析**，本项目已实现。
- **扫描件 / 图片型 PDF**（整页是一张位图）→ 必须 OCR，而 OCR 需要外部服务或本地模型，纯算法做不到。小程序端不可能跑 OCR 模型。

主人的样例 `许何禹帆(2026-2027-1)课表.pdf` 经检测是**文本型**：4.3 KB、2 条 FlateDecode 内容流、**157 个 `Tj` 文字操作符、0 个 `/Image`、0 个位图**。所以完全走纯算法路线。

### 实现

新增两个纯 JS 模块，不引任何第三方依赖：

- **`miniprogram/utils/inflate.js`** —— 自实现的 DEFLATE / zlib 解压（RFC 1950/1951）。
  小程序没有 node 的 `zlib`，也不方便引包，所以按规范实现了：zlib 容器、raw deflate、stored(00) / fixed Huffman(01) / dynamic Huffman(10) 三种块。用「码长计数 + 按码长取符号」解 Huffman，不做流式，一次解压整块（课表 PDF 体量足够）。
- **`miniprogram/utils/pdf-schedule.js`** —— PDF 解析主流程：
  1. 校验 `%PDF` 文件头，抓出所有 `/Filter /FlateDecode` 流并用 inflate 解压，取最大的一条（课表所在页）；
  2. 正则抓 `1 0 0 1 x y Tm ... (字符串) Tj`，得到「文本 + 坐标」。body 用「不含 `Tj` 的任意字符」限定，避免非贪婪匹配串到下一段（这个坑踩过一次，见下）；
  3. 解 PDF 字符串转义（`\n` `\ddd` 等），按 **UTF-16BE** 解码（教务 PDF 的常见做法：每字符 2 字节）；
  4. 用表头「星期一..星期日」的文字 x 减去固定内边距（33.92，该校模板恒定）定出 7 列左边界；用左侧「1..12」数字的 y 定行；
  5. **以「课程名行」为每门课的起点切分**：课程名行 = 不含 `(N-M节)`、不以 `/` 或 `:` 开头、不含「场地/教师/教学班」、不是纯 `★☆◇`；
  6. 正则提取 `(N-M节)` / 周次 / `场地:xxx` / `教师:xxx`，清洗掉课程名后的 `★☆◇`。

### 接入方式

- `pages/schedule/schedule.js`：`readScheduleFile()` 按扩展名分发 —— `.pdf` 用 `encoding: undefined` 读成 ArrayBuffer 走 `readSchedulePdf()`，其余按 utf8 走 `readScheduleText()`。两条路径统一收敛到 `confirmImport()`，确认弹窗会显示来源（「来自 PDF（2026-2027学年第1学期）」）。
- 粘贴通道加了保护：如果粘的是以 `%PDF` 开头的文本，提示改用「选文件导入」而不是报英文 JSON 错误。
- `pages/schedule/schedule.wxml`：按钮文案「导入 JSON」→「导入课表」，下方增加一行说明「支持教务系统导出的课表 PDF 和 JSON 文件，自动识别课程、节次、周次、教师与教室」。

### 解析过程中踩的两个坑

1. **正则跨越 `Tj`**：初版 `/...((?:\/F\d+ [\d.]+ Tf\s*)?)(.*?)Tj/g`，`.*?` 会一路吃到后面某个 `Tj`，导致每段取到错误的字符串、行序全乱（27 条退化成 15 条且课程名变成「班:(2026-2027-1)-…」）。改为 `((?:[^T]|T(?!j))*?)Tj` 限定 body 内不出现 `Tj` 后恢复正常。
2. **分块边界**：按 y 间距聚类、按「上一个节次锚点之后」切分都试过，前者会把上下两门课并块、后者会把课程名（在锚点**上方**）归给前一门课。最终用「课程名行」当切分点最稳，因为每个格子恰好一行课程名。

- **inflate 正确性另有独立测试**：对 5 类数据（短文本 / 高压缩文本 / 随机二进制 / 重复+随机混合 / 空数据）× 4 个压缩级别（0/1/6/9）共 20 例，结果与 node `zlib` **逐字节一致**；两条真实 PDF 内容流也与 `zlib.inflateSync` 一致；raw deflate（无 zlib 头）兼容；损坏数据返回 `null` 而不抛错。24/24 通过。

- 三个改动文件过 `node --check`，`git diff --check` 干净。

### 已知边界

- 目前适配的是**该校教务系统的课表 PDF 版式**（表头星期 + 左侧节次 + 单元格内「课程名 / (N-M节)周次 / 场地 / 教师 / 教学班」的行结构）。换学校若版式差异大，需要调整列内边距（`COL_PADDING`）与字段正则。
- 扫描件 PDF 不支持（技术上也做不到纯算法）。真遇到时的退路：教务系统一般同时提供 JSON/Excel 导出，或让学生用文字版 PDF。
- 微信开发者工具模拟器里从电脑对话框选文件仍是 `http://tmp/` 虚拟路径读不到，**真机从聊天选文件才正常**（PDF 与 JSON 同理）。

### 性能

纯字符串 + 数组运算，实测 4.3 KB PDF 解析在毫秒级。inflate 的 Huffman 解码每码长做了一次 `filter`（便于实现、性能非最优），对大 PDF（几百 KB）可能偏慢；课表 PDF 通常几十 KB，够用。若后续遇到大文件卡顿，可把 Huffman 表预展开成「按码长建索引表」再查。
